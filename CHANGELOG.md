# Changelog

All notable changes to cc-autodream. Format loosely follows Keep a Changelog.

## 2026-10-29

### Changed
- **The engine that writes the summary now reviews every harness's sessions in L1 by default.** Which harness holds a transcript and which engine reads it used to be one choice: each adapter's sessions went to its own engine. A run now has one reviewer, `AUTODREAM_L2_ENGINE` (else the first enabled adapter), and it reads every source's sessions unless `AUTODREAM_L1_ENGINE` (every source) or `AUTODREAM_L1_ENGINE_<NAME>` (one source) picks another. The source's own adapter still enumerates, linearizes and adds its triage notes; only the model call, its warmup and the network probe move. A host with one harness behaves exactly as before. **Upgrade note:** a host with both `claude` and `omp` enabled and `AUTODREAM_L2_ENGINE=omp` moves every Claude Code session from Haiku on the claude CLI to omp's L1 model on this upgrade. Set `AUTODREAM_L1_ENGINE_CLAUDE=claude` to keep them where they were.
- **`AUTODREAM_L1_MODEL_<NAME>` is keyed by the engine that makes the call, not by the harness that holds the session.** A model id belongs to an engine, so `AUTODREAM_L1_MODEL_OMP` is the model of every L1 call on the omp engine, whichever harness the session came from, and never reaches the claude CLI. A host whose harnesses each review their own sessions sees no change. One that moves a harness to another engine pins that engine's model, the same keying `AUTODREAM_L2_MODEL_<NAME>` already had.
- **A session with no usable L1 engine is retried once a later run gives it one.** Its error record counted as done, which held while the only cause was an adapter missing on disk. An engine choice naming no accepted adapter, a missing model and a failed login check are config, so the record now carries `no_engine: true`, and a later run of the date (a catch-up or `AUTODREAM_FORCE=1`) that resolves an engine and a model for the session's source drops it and triages the session.

### Fixed
- **`AUTODREAM_L1_REQUIRE_SERVED=1` no longer trusts a findings JSON to say who wrote it (#167).** It kept any record with `error` or `skipped` and no findings as the runner's own, so a substituted model that wrote `{"error":"unreadable","findings":[]}` left its session untriaged. The runner now marks each record it writes itself with `.served` reading `runner`, and that marker is the only thing that exempts a record from the verdict. Runner records written before this change are triaged once more.
- **A findings JSON holding two JSON values is no longer a finished triage.** Every check used `jq -e`, which judges only the last value, so a forged object followed by a valid one passed and L2 read the first. One definition, `L1_FINDINGS_OK` under `jq -s`, now requires exactly one value at every site.

### Added
- **`AUTODREAM_SESSION_ROOTS_<NAME>`** lists the session roots of one adapter other than claude, colon-separated, in place of its manifest's defaults, for a harness that keeps one store per profile.
- **Who each engine runs as, and which model answered each L1 call.** Each engine the run uses reports its login once through a new adapter verb, `whoami` (claude: `claude auth status --json`, no model call), logged and written to run-stats as `login_<engine>`. The claude L1 worker runs with `--output-format json`, and the new `served` verb reads the models that answered, the CLI's cost estimate at API prices and a verdict, `match` or `mismatch`, that knows the CLI's naming (`haiku` answers as `claude-haiku-5-5`). Every call goes to `findings/<date>/l1-served.tsv`. run-stats gains `l1_engine_<source>`, `l1_served_models`, `l1_served_mismatch`, `l1_served_unmeasured` (calls whose engine reports no model, such as omp), `l1_cost_usd_estimate` and `l1_cost_unmeasured` (calls left out of that sum, so an all-omp night does not read as free).
- **Both are record-only unless the host asks.** `AUTODREAM_REQUIRE_LOGIN` (space-separated `provider=`, `auth=`, `plan=`, `account=` pairs) hands an L1 engine whose login does not match no transcript, through the no-engine record above, and stops the run before it starts when the L2 engine does not match. `AUTODREAM_L1_REQUIRE_SERVED=1` discards the findings of any L1 call whose verdict is not `match`, an engine that cannot report one included. The verdict is stored beside every accepted answer (`<answer>.served`), and before L1 the run drops cached findings and chunk answers from earlier runs that no stored verdict vouches for and triages them again (`l1_cache_dropped`).

## 2026-10-27

### Fixed
- **The triage session carries the questions, not the report.** `bin/review.sh` passed the entire report through `--append-system-prompt` (~25KB on 2026-10-26) and launched with the literal prompt `go`. A report body narrating a night of firmware work — `sdb`, root status, `dlopen`, W^X — reads as an offensive-security engagement to model providers' content classifiers: every launch of the 2026-10-26 report was refused with `Opus 5.5's safeguards flagged this session ... Details: [cyber]`, and replaying the same request headlessly with `claude -p` reproduced it. The session now gets the report's questions section and a real one-line instruction.
- **The questions section has a machine-readable contract instead of a markdown heading.** Four consumers read it (`notify.sh`, `review.sh`, `question-streaks.sh`, `triage-dream.sh`) and each had its own approximation of "where does the section end": a heading match, a heading-to-next-`##` scan, a heading-to-marker scan. Gate review on `review.sh` alone spent five rounds on that difference — a heading inside a code fence, `~~~` fences, fence length, fence info strings — because every fix moved one parser and left the others. `PROMPT.md` now has L2 wrap the section in `AUTODREAM_QUESTIONS_BEGIN` / `AUTODREAM_QUESTIONS_END`, and `bin/report-format.sh` gains `report_questions` and `report_has_questions_block` as the single reader. `run.sh` treats a report from `AUTODREAM_QUESTIONS_EPOCH` (default 2026-10-27) onward as truncated when its block is missing or unclosed, so a bad block is rebuilt rather than handed to a consumer that would guess. Reports written before the block still read through the old heading fallback, which now lives in exactly one place.
- **The triage prompt never carries a partial question.** The inline cap (12KB) is all-or-nothing: a section that does not fit is not inlined and the prompt points at the report instead. Splitting a section at a line, an item or a fence and calling the remainder "the questions" had the session recommending on half a question.

## 2026-10-20

### Changed
- **CI runs the test suite as four parallel shards.** One job ran every test one after another in 6 to 7 minutes of a run that took 9. `tests/run-all.sh` now takes `RUNALL_SHARD=i/n` (every n-th test and unit suite, in file order) and `RUNALL_LIST=1` (print what a shard would run), and `tests.yml` runs four shard jobs plus a `test` job that waits on them, so the check keeps its name. The separate "unit suites" step is gone: `run-all.sh` already ran every one of those suites, so it repeated 47 seconds of work. In CI each shard finishes in about 1.5 minutes where the single job needed 6 to 7. `tests/run-parallel.sh [n]` does the same on one machine (about 6 minutes against 15 to 19 sequentially). `tests/shard.sh` proves the shards partition the suite exactly for n = 2, 3, 4, 6 and 8, refuses a malformed spec, and fails if a test is called directly instead of through the gate or the workflow's matrix and `/4` disagree. The `test` job uses `!cancelled()` so a superseded, cancelled run is not painted red, and `run-parallel.sh` stops its shards on Ctrl-C.
- **`AUTODREAM_QUESTION_LOCK_WAIT` (default 15) is how many one-second tries `question-streaks.sh` makes for a held lock.** The default is unchanged and a non-number keeps it. The streak tests hold a lock on purpose twice, to show that `clear` refuses to run while an update owns it, and waited out all 15 tries each time: 32 of the 46 seconds the slowest test in the suite took in CI, a floor no sharding can go below. They set it to 1 now.
- **`x-bookmarks.sh` no longer waits two seconds after the last page it will fetch.** It paced pages with `sleep 2` after every fetch, including the one that ended the loop, so each run paid for a wait that gated nothing. It now sleeps only when another page follows, and `tests/x-bookmarks.sh` shims `sleep` (recording the request) so the suite stops waiting too: 24 of CI's 123 seconds in one shard, and a new test pins both the two-second pacing and the absence of the trailing wait.
- One omp chunking assertion no longer depends on `TMPDIR` length. It parsed the first chunk's header line, which is 391 characters under a 9-character `TMPDIR` and is cut at the slimmer's 400-character cap, so a longer one made `jq` print nothing. It now checks the line's fixed prefix.

## 2026-10-19

### Changed
- **The report's two contracts are read in `bin/report-format.sh` and nowhere else.** The open-questions marker sed was copied in `report-format.sh`, `notify.sh` and `question-streaks.sh`, the marker presence grep in three places in `run.sh`, and the sentinel grep and awk in `run.sh` (four times) and `triage-dream.sh`. They are now `report_marker_count`, `report_has_marker`, `report_has_sentinel`, `report_body`, `report_after_sentinel` and `report_pin_lines`. The marker count stays strict (a well-formed comment) and the presence check stays loose (any line with the key), so `question-streaks.sh` still refuses to clear a streak on a malformed marker while `run.sh` still accepts a truncated report that carries the key. `run.sh` stops at startup with `FATAL` if the lib is missing, instead of failing on the first report read. `tests/report-format.sh` compares each helper with the code it replaced over 16 fixtures, a missing file among them (119 assertions).
- **The L2 system prompt is one file, `prompts/L2_SYSTEM.txt`.** The same 657 characters sat inline in the claude adapter, the omp adapter and `run.sh`'s built-in claude fallback. They state the stdout grammar that `bin/report-format.sh` parses (the report, `AUTODREAM_REPORT_END`, the optional pin block, the summary), so a drift between a copy and the parser would show up only as an L2 run whose output the runner cannot split. `bin/l2-prompt.sh` reads the file and returns 2 with a message when it cannot, and both adapters' `l2-argv` then exit 2 and print no argv, where an engine without the prompt would otherwise run with no word on where the report goes. `run.sh`'s fallback builds no argv without it and logs why. `install.sh` links the prompt and the loader. `tests/l2-prompt.sh` (25 assertions) pins the text, the missing-file failures and that no script keeps an inline copy.

## 2026-10-18

### Added
- **A global `/autodream` skill.** `install.sh` links `skills/autodream` into `~/.claude/skills/`; `--no-skill` skips it. A custom install dir links it only when `AUTODREAM_SKILLS_DIR` is set, because the skill looks for the scripts in `~/.claude/autodream`. The skill logs decisions under `## Triage in progress` and writes `## Triage decisions` only after the last question, so an interrupted session does not hide the rest. The skill prints `now triaging N issues from dates A to B` or `no issues to address!`, starts a dream through `autodream-now.sh`, recommends a yolo session, and walks the open questions of every report that has no `## Triage decisions` heading, oldest first. The count comes from the new `bin/pending-triage.sh` (`--summary`, `--list`), which looks back `AUTODREAM_PENDING_DAYS` (14) days. `review.sh` and `pending-triage.sh` now read the open-questions marker and the triaged heading through the new `bin/report-format.sh`. `tests/pending-triage.sh` has 14 assertions.

### Changed
- **`AUTODREAM_MIN_USER_TURNS` and `AUTODREAM_MIN_MINUTES` are checked at startup.** A non-number used to make the noise gate's `jq` fail with its error discarded, so every session went to a model call and nothing said why. The run now refuses to start, like the timeout knobs.
- `tmo` and `repo_slug` moved into `bin/portable.sh`. They were byte-identical copies in `prune-worktrees.sh` and `triage-candidates.sh`, and `tests/portable.sh` now pins them.

## 2026-10-14

### Added
- **The report suggests triaging a touched repo that has a pile of untriaged issues.** New `bin/triage-candidates.sh` resolves the working directories of the night's sessions to GitHub repos, counts open issues with no triage state label (`needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`) or with `needs-triage`, and writes `findings/<date>/triage-candidates.{md,tsv}` when a repo has `AUTODREAM_TRIAGE_MIN` (3) or more. `PROMPT.md` copies the table into a "Repos to triage" section that never counts toward the open-questions marker. A repo is held back for `AUTODREAM_TRIAGE_COOLDOWN_DAYS` (7) unless its untriaged count grew by `AUTODREAM_TRIAGE_GROW` (3); a repo that was never triaged counts every open issue, so its first triage is suggested too. A repo where the viewer lacks triage permission, or that is archived, is never suggested. On by default, read-only, never fails the run. `AUTODREAM_TRIAGE_SUGGEST=0` turns it off. `run-stats.txt` gets `triage_candidates:`.
- **The pruner keeps a write-ahead ledger, and refuses to remove anything it cannot log.** `AUTODREAM_PRUNE_LEDGER` (default `~/.claude/autodream/prune-ledger.tsv`) is append-only. Each removal writes an `intent` line before the first change, with the repo, branch, local tip, remote tip, worktree path, the PR URL, state, head and base that prove it, and the exact commands that restore the local and the remote branch. One line follows per step (`worktree-removed`, `remote-deleted` or `remote-kept`, `local-deleted`), then `complete`; a run is bracketed by `run-start` and `run-end`. If the ledger cannot be opened or an `intent` cannot be written, the item stays (`ledger-unwritable`, `ledger-write-failed`). A dry run writes nothing. Before the first change the tip is pinned as `refs/prune-ledger/<run id>/<branch>`, because a squash-merged tip is otherwise unreachable once the branch and the remote ref are gone and `git gc` would prune it; a failed pin keeps the item. The recover commands use single-quote quoting that bash, zsh and fish all read, and carry the push half only when the remote branch existed. A watchdog stop writes an `interrupted` line, and a step line that could not be written marks the removal `ledger-incomplete`. 97 assertions now, including one that runs `git gc --prune=now` and then the recorded recover commands, for a branch with a quote in its name too, and checks both branches come back at the same tip.

## 2026-10-13

### Added
- **The nightly run can prune finished worktrees and branches (`AUTODREAM_PRUNE_ROOTS`, off when unset).** New `bin/prune-worktrees.sh` searches the listed directories for repos and, in each, removes worktrees under `.claude/worktrees/` and `.worktrees/` plus local and remote branches whose work has landed: a PR from the same repo merged into the default branch at the branch tip, a PR closed unmerged for 7 days with its head at the tip and the branch fully on the remote, or (for a repo with no remote) a tip already in the default branch. It keeps anything with an open PR or an open PR targeting it, uncommitted files, an edit in the last 12 hours, a lock, a rebase, submodules, a protected or long-lived branch name, or no proof. The remote branch is deleted by a push that leases on the proven commit, so a later push is never lost and no branch name goes into a URL. At most 25 removals and 1200 seconds per run. Every network call and `trash` has a timeout (a built-in watchdog when the machine has no `timeout` or `gtimeout`), and a hard stop 120 seconds after the budget writes the report and exits. Worktree directories go to the Trash. `run.sh` calls it after the report inputs are collected, writes `findings/<date>/worktree-prune.md` and `.tsv`, and records `worktree_prune:` in `run-stats.txt`. A failure logs and never costs the report. `tests/prune-worktrees.sh` runs real temporary repos with `gh` and `trash` shimmed (76 assertions, each finding from three review rounds pinned as a keep), and CI runs it. `install.sh` links the script.

## 2026-10-07

### Changed
- **Layer 1 on the claude adapter runs `claude-haiku-5-5`, at effort `high`, with Claude Code's default system prompt replaced.** `AUTODREAM_L1_EFFORT` (or `_CLAUDE`) takes `low|medium|high|xhigh|max|off`. The warmup uses the same flags as a worker. Measured on one real transcript slice: $0.159 per worker against $0.215 with the appended prompt, three findings each.
- **CI no longer starts a macOS run per push.** A newer push to the same PR or ref cancels the older run, a docs-only change and a draft PR start nothing. 100 runs in two days (83 on one) at about 11 macOS minutes each had been billing at the 10x macOS rate.
- **The suite runs on Linux.** New `bin/portable.sh` wraps the BSD-only `date -v`, `date -j -f`, `date -r <epoch>` and `stat -f` that the scripts and tests called directly; `tests/portable.sh` pins both branches. `canonical_project` now refuses a missing path on GNU `realpath` too. `tests.yml` runs on Ubuntu; the launchd suites (`install-*`, `scheduler-label`, `autodream-now`) moved to `launchd.yml`, which runs on macOS only when a launchd file or `portable.sh` changes, weekly in full, and on dispatch. `install.sh` links `portable.sh`.

## 2026-10-04

### Added
- **The slimmer can reshape a Claude Code transcript and keep every line, both off unless asked for.** `AUTODREAM_SLIM_RESHAPE=1` drops Claude Code bookkeeping by a DENYLIST of record types and attachment subtypes (an allowlist of user and assistant would delete every OMP record, and a subtype nobody has seen is kept) and rebuilds each kept Claude record with `type` and `timestamp` first and the message reduced to `role` and `content`, so the 400-character line cut cannot take the timestamp. On a real 3,479-line session 36% of the lines were conversation, 24% hook and reminder attachments and 21% mode, permission-mode, last-prompt and bridge-session records, so the positional head/tail view spent its budget on bookkeeping. `queued_command` and `skill_listing` attachments, every `system` record but `stop_hook_summary` and `turn_duration`, `pr-link` and compaction summaries are kept; OMP and unknown-schema records come out exactly as they do without the reshape. `AUTODREAM_SLIM_FULL=1` keeps every surviving line with no head/tail, no byte cap and no footer. Nothing sets either yet, so a plain call writes the same bytes as before: pinned by a golden digest over a 2,800-line fixture taken with the previous script (reverting the footer guard fails it), and Sean Perkins checked it on 16 real transcripts, Claude and OMP. One change that is not byte-level: the output file is now mode 0600, because it is derived from a transcript (a destination the caller already made is tightened too). Split out of https://github.com/STRML/autodream/pull/120 at the maintainer's request; the chunked reader that uses these modes follows in that PR.
- **An L2 attempt that dies to a signal now leaves a diagnostic record (Refs https://github.com/STRML/autodream/issues/42).** L2 attempt 1 has exited 143 with a bare `Execution error` on six nights since 2026-08-01 and nothing in the log says who sent the TERM; `run.sh` sets no L2 timeout, so it came from outside. When an attempt exits 143, 137 or 124, `run.sh` now writes `findings/<date>/l2-attempt-N.diag` with the start, end and elapsed time, the exit code, the engine's pid (it now starts through a one-line `sh` that records its pid and `exec`s, so argv, stdin and the pid are unchanged), the runner's parent chain at start, load and memory pressure at start and end, the kernel's last sleep and wake times, the engine's state at the end, every other autodream or claude process, and the launchd job list and state (`AUTODREAM_LAUNCHD_LABEL`, else `XPC_SERVICE_NAME`, when set). Each probe is bounded to 3 seconds and cannot fail the run. A clean attempt, and an ordinary failure such as exit 1, write nothing. Diagnostics only: no retry, timeout or exit-code logic changed, and the issue stays open until the sender is known. Four cases in `tests/run-all.sh`, with a mock L2 that exits 143 or 137.

### Changed
- **Opt in: Layer 1 can read a long session in full instead of 17% of its lines (`AUTODREAM_L1_CHUNK_BYTES`, default 0 = off).** With `AUTODREAM_L1_CHUNK_BYTES=300000` a transcript whose worker input is over that many bytes is split at line boundaries (`bin/chunk-transcript.sh`), read by one worker per chunk, and merged without a model call (`bin/merge-chunks.sh`) into the one findings JSON per session that Layer 2 reads: the goal from the first chunk, the outcome from the last, findings unioned, tagged with their chunk, deduplicated on (category, what), most severe first, capped at ten. At most `AUTODREAM_L1_MAX_CHUNKS` (8) chunks are read; over that the first half and last half are kept, the middle is dropped and counted. **This multiplies Layer 1 calls for every install**: an oversized session costs up to 8 calls instead of one per round, so a night costs up to *oversized sessions x 8* plus one per other session, and a session takes up to 8 x `AUTODREAM_L1_TIMEOUT` of wall time (its chunks run in sequence in one slot). Measured on one real day of this host (70 oversized sessions): 73 calls, two sessions chunked, nothing elided; the old view showed 22% of the conversation lines of those sessions, the new one all of them. Real-model replay of five oversized sessions of 2026-10-02 (four chunk, 11 chunks in all; one fits in one chunk), one pass each: claude-haiku-4-5 found 3 findings with the old view and 8 with chunking, neuralwatt/glm-5.3-flash 12 and 36; `l1_findings_with_error` 0 in all four runs and no session lost. Unset or 0 is today's head/tail slim exactly: against the previous runner, with it off, every transcript a worker reads, every prompt and every findings JSON was byte-identical on a fixture run, and on a replay of the real 2026-10-02 the 70 findings matched.
- A chunk answer is untrusted input. `merge-chunks.sh --check` is the one definition of a usable one (exactly one JSON value, an object, no `error` key, a `findings` array: plain `jq -e` judges only the last value in a file, so an error object followed by a good one used to pass), and the merge refuses to run around a chunk that fails it. A failed or invalid chunk is redone alone; finished chunks are reused. A chunk failure is a worker failure: the same `.err` evidence (the first failing chunk's), the same classification (`failure-class.sh`), the same no-route and provider-refusal verdicts, which stop the other chunks of that session and defer the date, and the same stub only on the last round, never from part of the chunks. The circuit breaker counts a finished chunk answer as progress. A failed chunker, or a cap of 1, never hands a worker the whole uncapped transcript. Chunk answers live under `findings/<date>/.chunks/<hash>/` with a `.chunkout` suffix, so nothing that scans for findings JSONs can mistake one for a session; the chunk inputs, which are transcript text, are mode 0600 and removed by the dispatcher after every round.
- `run-stats.txt` gains `l1_chunk_bytes` (0 when off, including when a helper is missing, which is also logged), `l1_max_chunks`, `l1_chunked_sessions`, `l1_chunks`, `l1_chunk_calls` (engine calls actually made, retries included, reused answers not) and `l1_chunks_elided`.
- **The Activity snapshot separates a fanout from the sessions that spawned it (#79).** On 2026-09-08 a parent spawned 29 workflow workers and 11 skeptics and the report counted 72 sessions and an overlap of "78 of 72"; on 2026-09-20 all 13 non-gated sessions were subagents. `run.sh` now writes `sessions_top_level`, `sessions_nested`, `fanout_parents` and `largest_fanout` to `run-stats.txt` (ungated sessions, the set the report's N counts) and `fanouts.tsv`, one worker-to-parent row per nested transcript. `PROMPT.md` tells L2 to report "N sessions (T top-level, W nested workers under P parents, widest fanout L)", rank projects and models over top-level sessions, and keep the workers' findings in Top patterns and Per-project notes. Nested transcripts are still triaged one by one. An omp child whose parent file was deleted is still marked `nested`: `adapters/omp/linearize.sh` now also reads the stamped directory name (`<ISO stamp>_<id>`), which a project bucket never has.
- **The multi-clauding count leaves nested workers out.** A claude subagent (`isSidechain`) or omp child (`nested`) overlaps its parent and its siblings by construction, the same reason advisors were already dropped. The count still includes gated top-level sessions, so it can exceed the session total; `PROMPT.md` now has L2 write "incl. gated" beside it instead of re-explaining the gap each day.

### Fixed
- **`wait_for_network` stops probing once the cap is spent (https://github.com/STRML/autodream/issues/137, https://github.com/STRML/autodream/issues/138).** The per-URL probe limit was floored at 1s for every URL, so with several dead providers the pass ran about one second per extra URL past the cap before the cap check fired. Only the first probe of a pass keeps the floor now (a cap of 0 still asks once); later URLs end the pass when nothing is left. The test that should have caught it allowed 5s against an expected 4s on a whole-second clock. It now probes six dead hosts against a 2s cap and allows 4s: the fixed loop measured 2s and the broken one 7s.
- `prompts/SESSION_TRIAGE.md` no longer labels `buggy_code_shipped` a "PILOT category". Its pilot week ended on 2026-07-28 with the category promoted (`PROMPT.md` lifts its quarantine), so the label told the L1 worker the category was provisional. Prompt-only: no code, schema or counter moves.
- **A failed `seen.jsonl` write no longer reads as "no unread bookmarks" (#108).** `collect_bookmarks` ignored the return of `merge_state`, so with no prior state and an unwritable state directory the fetch succeeded, the state update failed, `emit_unread` read nothing, and the report was told the inbox was empty. A failed update now writes `# x-bookmarks: fetch failed — could not update <seen.jsonl>, so this run's bookmarks were not recorded`, the header L2 already reports as a broken walk. With earlier unread bookmarks on disk they are still shown on both the success and the failed-fetch path, under a note that names the failed update. Three cases in `tests/x-bookmarks.sh`; they skip when the user can write to a read-only directory (root).
- **Pins a killed or failing run never finished storing are applied by the next run (https://github.com/STRML/autodream/issues/72, https://github.com/STRML/autodream/issues/69).** A new `sweep_stranded_pins` step runs before the idempotency guard and reapplies `pins.jsonl` for any date in the trailing week that has a complete report, its `pin-projects.tsv`, and either no `pins-result.txt` (the run died before the pin step) or counters with failed, `cli_missing`, unreadable or held pins. The ledger keeps the rerun from storing a pin twice. To make that possible the runner now writes `pins.jsonl` and `pin-projects.tsv` before it stages the report, so a complete report always has its pins beside it.
- **The question streak update runs before the pins and `notify.sh` (https://github.com/STRML/autodream/issues/77).** A hung `AUTODREAM_OPEN` command or Mnemopi store used to hold the run ahead of `question-streaks.sh`; once the run died there, the next trigger skipped the date and the report was never counted, so a stale question missed its escalation. The update only reads the report and writes one local file, so it now goes first. The nightly banner and the escalation banner swap order.
- **Memory pins: the ledger can no longer be emptied by a worker, is keyed on the bank, and stale counters are never logged (https://github.com/STRML/autodream/issues/76, https://github.com/STRML/autodream/issues/70).** `run.sh` snapshots `pins-applied.tsv` before any model runs and restores it before the pins are applied, since L1 workers hold the Write tool (L2 no longer does). The ledger hash now includes the resolved bank, so a forced rebuild that resolves a project to another directory stores its pin in that bank. `apply-pins.sh` exits 3 and stores nothing when it cannot clear `pins-result.txt`, exits 3 when it cannot write it, and `run.sh` then logs the counters as unavailable. The matrix and counter lists in the design docs gain the `pins_unsupported_harness` outcome.
- **Project attribution survives nested session roots and non-object findings JSON (https://github.com/STRML/autodream/issues/73).** `session_project` now takes the directory under the longest root that holds a session, so `SESSION_ROOTS=/c:/c/projects` names `<bucket>` instead of `projects` and stops merging every bucket into one project whose pins are refused. The project-field normalization skips a findings file that is valid JSON but not an object (`[]`, `null`) instead of dying partway, and `run.sh` logs a warning when that pass exits nonzero instead of claiming it normalized.
- **The idempotency guard no longer treats a half-written report as a finished date (#111).** `run()` skipped any date whose report was merely non-empty, while `report_complete` (and `unassembled_dates()`) require the `autodream:open-questions=` marker. A marker-less report, left by a run killed mid-write, made every later trigger a no-op and `question-streaks.sh` parse it as zero questions. The guard now calls `report_finishes_date`: non-empty and carrying the marker, or dated before `AUTODREAM_MARKER_EPOCH`, the same exemption `unassembled_dates()` applies. An unfinished report logs `lacks the open-questions marker`, the run rebuilds, and the existing move-aside sets the old file aside as `.stale-<epoch>`, kept if the rebuild fails and discarded once a complete report replaces it.
- **The network check asks the provider each layer calls, and its cap bounds the probe (#109, #110).** `net_up` probed `api.anthropic.com` whatever ran, so an omp L1 on deepseek was gated on Anthropic: a dead deepseek route read as healthy and a dead Anthropic one deferred a run that did not need it. The URL now comes from the layer's own model (`provider_probe_url` in `bin/adapters.sh`: the part before the slash, `claude` always Anthropic), resolved once with the L1 models and held in `AUTODREAM_L1_PROBE_URLS` for the worker's failure probe, and from the L2 engine's model for the L2 retry gate and the closing probe. Known hosts: anthropic, deepseek, neuralwatt, zai, runinfra; `AUTODREAM_NETUP_URL_<PROVIDER>` pins one. The pre-dispatch gate opens when any enabled provider answers, so a dead deepseek route does not hold back claude sessions that never touch it; a worker that does need the dead one fails, is classified as an outage by its own probe, and defers the date. A provider with no known host cannot be asked, so it reads as up, the same bias as a missing `curl`. The worker's `.err` now names the host that was down.
- `wait_for_network` measured its cap in slept seconds only, so each probe (up to `AUTODREAM_NETUP_LIMIT`, 8s) ran past the bound and a hung one was noticed after it returned. The cap is wall-clock now, a probe gets at most what is left of it, and `network_down_seconds` counts only a wait that really happened. The first probe always runs, so a cap of 0 still asks once. The other half of #110 (the omp-log capture mtime race) went with the code that did it: nothing in `bin/run.sh` captures an omp log any more.
- **Two runs for the same date can no longer share a findings dir (#55).** The idempotency guard is a check, and launchd serialises a label only against itself: `autodream-now.sh` runs under its own `.ondemand` label, so an on-demand run and a scheduled trigger for one date were two processes writing one `sessions.txt`, one sidecar set and one report path (the second run's move-aside even carried off the first one's report mid-build). `run()` now takes a per-date lock before it mutates anything: `mkdir $AUTODREAM_DIR/locks/run-<date>.lock`, holding the owner's pid and process start time. A run that finds a live holder logs it and exits 0, as the guard does. A holder that is gone, or whose pid now belongs to another process, is stale and is reclaimed (the stale directory is renamed aside, so two reclaimers cannot delete each other's new lock). The lock sits outside the findings dir, so clearing a date's findings for a rebuild cannot release it under a live run, and an EXIT trap releases it, only when the pid file is this process's.
- **A forced rerun no longer reports sessions its worklist does not own (#56).** L2 reads every findings JSON in the date's directory, and a rerun reuses the directory, so the JSON of a session that was pruned, deleted, rehomed or un-indexed since the first run still reached the report, and nothing counted it as unreconciled. Before L1 now, `reconcile_findings_with_worklist` moves each `<hash>.json` outside this run's worklist into `findings/<date>/outside-worklist/` (counted in `l1_findings_outside_worklist` and named in the log), which L2's glob does not reach. It is moved, not deleted, and a JSON in `outside-worklist/` whose session is back in the worklist is restored before the pre-L1 snapshot, so a later rebuild does not triage it twice. This replaces #113's leave-in-place behaviour, which counted the stale JSONs but let L2 read them. The ownership test is the same one as before (the hash of every line of `sessions.txt`).
- **The L1 fan-out carries a session path byte for byte (#54).** `dispatch_l1` read `sessions.txt` through `xargs -I {}`, which turned a tab into a space, deleted a backslash and died on a quote with `unterminated quote`, so one such path cost the whole night's triage. The refusal added in #53 only made that loud. Workers now get their path NUL-delimited (`tr '\n' '\0' | xargs -0 -n 1`; `sessions.txt` stays line-based, so its sha1 keys and archived findings dirs are unchanged), which also lifts the 255-byte limit `-I` put on the argument. The worker's own JSON (unreadable, noise-gated, no engine, the metadata stub) is built with `jq` instead of `printf`, and the rewrite of the temp copy's path back to the session path is a literal jq replace instead of `sed s#..#..#`, which read a `#` or `&` in a path as its own syntax. Backslashes, double quotes and apostrophes are therefore triaged like any other path. A newline or a tab is still refused and counted in `sessions_rejected_path`: the line-based lists and the tab-separated `pin-projects.tsv` and source map cannot carry them.
- **A killed adapter no longer leaves its temp files behind for good (#57).** `adapters/claude/adapter.sh` writes `stats` and `slim` output through `<out>.tmp.XXXXXX`, and `slim-transcript.sh` writes its own `<dst>.pre.jsonl`; a run killed mid-flight (this pipeline's normal failure) left both, and nothing removed them. A signal trap in the adapter would hang the run, so `run.sh` now sweeps `*.tmp.??????` and `*.pre.jsonl` out of the findings dir before L1 (`sweep_killed_leftovers`), where a killed process cannot skip it, and logs how many it removed. Nothing reads those names, so this is housekeeping, not a correctness change.
- **`autodream-now.sh` no longer kills a run that is still going (#78).** Every on-demand run for an install shares one launchd label, and the unconditional `launchctl bootout` before `bootstrap` evicted whatever held it. Launching a second date while the first was in L1 (or after `--watch` gave up at 90 minutes) left no report and no error, and orphaned the first run's workers. It now asks `launchctl print` for the label first. A loaded job with a live pid is refused (exit 75) and the message names the date that holds the label; a loaded job with no pid has finished and is booted out as before. The check runs before the plist is rewritten, because the holder's date is read back out of the old plist. `tests/autodream-now.sh` is new and runs under a mock `launchctl`; it is in CI and in `tests/run-all.sh`.
- **omp children are sidechains, and harness-injected turns are not human ones (#114, items 2 and 3).** `adapters/omp/stats.sh` set `isSidechain` from a custom `agent` or `subagent` record that omp never writes (its only custom types are `tool_execution_start` and `session_exit`), so the flag read false for every file and the noise gate's sidechain exemption could not apply to a child. It now follows provenance, the same rule `is_advisor` and `nested` already use: an advisor or a task child is a sidechain, whether the stats script is handed the raw file (its own directory plus `.jsonl` is a file) or the linearized copy (the `autodream_meta` record). A raw child whose parent file is gone is still nested when its directory is named like a session file (`<ISO stamp>_<id>`). It also stops counting a user-role message with `"attribution":"agent"` as a human turn, in `user_message_count` and in `user_turn_timestamps`. In a 400-file sample of one host every advisor user message and 457 of 485 task-child ones carried it, so an advisor cleared the two-turn gate on its own prompt stream, and children paired with their parent in the overlap pass on timestamps no human wrote. A message with no attribution field counts as human, as before the field existed; `turn_count` still counts every message. A child now reads zero human turns and is exempt from the gate by provenance.
- Item 4, a timestamp as the project of a nested session, was already fixed: the project is the directory directly under the session root at any depth (`session_project` in `bin/run.sh`, #68), and the findings `project` field is normalized from it. `test_omp_nested_child_is_a_sidechain_of_its_bucket` now pins it for an omp advisor child.
- **The X bookmarks queryId walk always requests every suffix variant of the Bookmarks bundle (#107).** `detect_query_id` stopped at 24 requests in total, counting the page's own `main.` and `bundle.Bookmarks` URLs ahead of the 17 reconstructed suffix variants, so a page listing more than 7 such URLs cut the last variants off and reported "could not find the Bookmarks queryId" with the bundle reachable. The page URLs now have their own cap of 8 and the suffix list is always walked in full. `tests/x-bookmarks.sh` has a walk test with 30 page URLs and the real bundle behind the last suffix.
- **A session belongs to the day its records say, not the day its file was last written (#113).** Enumeration was `find -newermt DAY ! -newermt NEXT`, so a session touched again after its day closed (a resumed session, or an OMP title rewrite) vanished from every later rebuild of that day, and from the next day's report too unless a run for that day happened. A rebuild of 2026-08-21 lost two parents whose advisor sidecars it kept, and a stale `<hash>.json.err` with no `.json` was then neither retried nor counted. `run.sh` now bounds mtime from below only and keeps a file when it holds a record timestamped inside the local report day (`bin/session-window.sh`, both adapters, the top-level `.timestamp` string they both write). The session is back in `sessions.txt`, so the existing retry loop retries its stale `.err` and the missing count sees it. The adapter contract is unchanged: the runner passes `enumerate` an upper date of the report day plus five years.
- A transcript that spans several days is cut to the report day before the stats and the L1 worker see it, so `duration_minutes`, the user-turn and tool counts, the noise gate, the overlap pass and the oversized gate describe that day. A transcript wholly inside the day is read exactly as before. An OMP session is linearized first and the live chain is what is cut, never the raw tree: cutting the tree leaves a dangling `parentId`, which the linearizer refuses. The slice starts at a root (`parentId` null) so no `parentId` in it points outside it. A worker handed a slice is told so in its prompt.
- A transcript with no timestamps is placed by its mtime, so a no-clock file touched after its day still drops out of that day's rebuild; there is nothing else to place it by. A file modified since the day began that holds records and none inside the day is no longer triaged under that day, which an mtime-only run would have done.
- **`encode_project` encodes a non-ASCII path the way Claude does (#59).** It was byte-wise, so `é` became two dashes. Measured 2026-10-04 with `claude -p` in a directory named `café-日本-😀`: Claude writes one dash per UTF-16 code unit, so a BMP character is one dash and an astral character (an emoji) is two. A path with a multi-byte character used to split its project in two silently. `tests/lib-project.sh` pins the measured bucket name.
- **The SIGTERM assertion in `tests/adapter-claude.sh` no longer passes when `ps` cannot run (#64).** An empty `ps` read meant both "the process exited" and "ps is not permitted here", so a sandbox that refused `ps` made the check that guards against a signal trap in the adapter report green without testing anything. The suite now probes `ps` against its own shell first and fails loudly when that read is empty, and a stub `ps` that exits 1 pins the probe.
- **The sibling drift check is retired (#106).** `bin/check-shared-drift.sh`, `shared-with-sibling.txt`, the worktree test for the script and the last step of `tests/run-all.sh` that ran it are gone, and so is the CLAUDE.md section that described them. omp-autodream is archived, so the check compared five helpers against a repo that no longer changes; an empty manifest also reported ok after comparing nothing, which is moot with the script gone. CLAUDE.md keeps the 2026-09-11 incident that justified the check and the lesson that outlives it.
- **The install-dir resolver lives in one file (#112).** `autodream-note.sh`, `vault-notes.sh`, `review.sh`, `autodream-now.sh`, `question-streaks.sh` and `notify.sh` each carried their own copy, and the copies had drifted: they disagreed on which files prove a directory is an install (`config` and `PROMPT.md`, or `config` and the OMP-only `l1-no-advisor.yml`), on whether to warn, and `notify.sh` never looked at its own location. `bin/lib-install-dir.sh` is the single `resolve_install_dir`, and `install.sh` links it. An installed script that starts before `install.sh` has linked the helper finds it through its own symlink, so a merge cannot break a nightly in between. Markers are now `config` or `PROMPT.md`, so a bare `notify.sh` run from an install uses that install instead of the legacy default. `tests/install-dir.sh` covers the resolver and each caller.
- **An interrupted test run no longer leaks its temp directories (#63).** Eight suites (`adapter-contract`, `lib-project`, `adapters`, `cookie-cadence`, `preflight`, `review-skip`, `x-bookmarks`, `run-all`) made `mktemp -d` dirs and removed them on their last line, and macOS never collects a non-empty tree under `/tmp`. `tests/lib-tmp.sh` gives each suite one temp root, points `TMPDIR` at it and removes it on exit, Ctrl-C and TERM, which also covers `mktemp` calls inside `$(...)` that no variable could track (`adapters.sh` appended to a list that died with the subshell). `tests/tmp-cleanup.sh` SIGTERMs each suite right after its first temp dir appears and fails on any leftover; it is in CI and `tests/run-all.sh`.

### Added
- **`mods/autodream-focus`, an opt-in Claude Code mod (by Sean Perkins, https://github.com/STRML/autodream/pull/146).** A `+ autodream focus` button on every prompt and reply tags a turn for the next nightly run. The mod writes `tags.jsonl`; `bin/vault-notes.sh` reads it as a third capture surface, turns each pending tag into a `## note: focus-...` block in `operator-notes.md` (header gains `tagged: N`), and records it in `tags-consumed.txt` only after a complete report. A tag is its id and its `taggedAt`, so untagging and tagging a turn again offers it again; rebuilding a consumed date keeps its tags; an unreadable `tags.jsonl` is reported as `UNREADABLE`; a tag with an unparseable `taggedAt` is dated by the report, not 1970. `install.sh` does not load the mod. The mod honors `AUTODREAM_TAGS_FILE` as `bin/vault-notes.sh` does.

Grounding is not left to the model. `bin/dream-grounding.sh` runs fixed, model-free checks in the runner (is the skill the report names installed, is the allowlist key it proposes in `permissions.allow`, does the commit it cites resolve in a repository the night triaged) and writes `findings/<date>/triage/grounding.json`; a check that cannot run says `unknown`, never `absent`. The model gets Read and Glob over that directory and prints the worklist on stdout behind `AUTODREAM_REPORT_END`; the runner writes the file. The engine is an adapter, `AUTODREAM_L2_ENGINE` and `l2-argv`, so no binary, tool list or model is named in the new code. `install.sh` links `triage-dream.sh`, `dream-grounding.sh` and `TRIAGE_DREAM.md`. `tests/dream-triage.sh` is a new unit suite, in CI and in `tests/run-all.sh`; the mock writes `triage-*` capture files, not `l2-*`. It overlaps neither `review.sh` (an interactive walk through the open questions) nor `citation-check.sh` (which resolves session hashes), and reuses neither.
- `run-stats.txt` keys `sessions_out_of_window`, `session_window` (`on`/`off`), `sessions_windowed` (triaged sessions cut to the day) and `l1_err_files_orphaned`, the `.err` files with no findings JSON whose session is not in the run's worklist, which nothing retries. They are logged by hash. A stale `.err` is reported, not retried: the `.err` is the only record of which session it was, and a worker with the Write tool could have put any path in it. `l1_findings_outside_worklist` counts findings JSONs left by an earlier run that this run's worklist no longer owns (L2 reads them all); they are named in the log and left in place.

The window is also off, with `session_window: off`, when `bin/session-window.sh` cannot be found, the report day does not convert to epoch bounds, or this host's `find` rejects the far upper date, so a degraded install reads exactly what it read before.

- `tests/replay.sh --ingest` stages every session modified from the date until five years after (the runner's own reach), not only those last modified on the date, so it can see the sessions this change recovers. A replayed date on which every staged file holds no record in the day is a WARN, not a FAIL.

## [Unreleased] — 2026-05-30

### Added
- **`review.sh` skips reports with nothing to triage.** Most nights the report has no open questions, and launching a Claude session just to be told "nothing to do" spent a full session's tokens to print one line. `review.sh` now decides that itself and prints the line instead, exiting 0 — same for a report that already carries a `## Triage decisions` section. `PROMPT.md` gained an output contract for it: L2 must end the Open questions section with `<!-- autodream:open-questions=N -->`. Reports written before that marker fall back to a prose check (the "None that clear the triviality gate" shape L2 has used consistently), and anything unrecognised launches the session as before — a wasted session costs tokens, a false skip buries a real question. `--force` bypasses both checks and is carried through into the cmux re-invocation, so forcing a triaged report doesn't open a workspace that instantly exits. The check runs before the cmux branch, so a skip never spawns a workspace just to print to a window that dies. New `tests/review-skip.sh` covers the decision (marker, prose fallback, empty-day stub, unclassifiable, triaged in both bullet and numbered styles, `--force`, latest-report resolution, missing report).
- **On-demand runner (`bin/autodream-now.sh`).** Runs the pipeline NOW via a transient one-shot launchd agent, so it survives the ~10-minute cap on Claude Code background Bash tasks (and ssh disconnects) — launchd owns the process, no time cap. `[DATE] [--force] [--watch] [--dry-run]`. Auto-detects everything: resolves its own symlink to find `run.sh`, picks the scheduled plist whose `ProgramArguments` reference `run.sh` (not the sibling `*-review` job) for its label namespace, and detects uid + `claude`/`git` dirs for the agent PATH. `RunAtLoad` is the only trigger (no `kickstart`, so a fast idempotency no-op can't double-run). Never touches the scheduled nightly job. `install.sh` symlinks it alongside the others.
- **Upstream changelog awareness.** `run.sh` clones/pulls `anthropics/claude-code` into a persistent cache and diffs `CHANGELOG.md` over the run's date window (by real commit date, since the raw changelog carries no dates but the git history does). Layer 2 reads the result and writes an "Upstream harness changes" report section flagging releases that change how we work or affect active projects. Degrades gracefully with no git/network. Knobs: `AUTODREAM_CHANGELOG`, `CLAUDE_CODE_REPO`, `CHANGELOG_REMOTE`.
- **Self-pollution prevention.** Both layers now pass `--no-session-persistence`, so `claude --print` workers no longer leave their own transcripts in `~/.claude/projects/` for the next run to re-triage (this had been ~90% of the corpus). New `bin/prune-self-sessions.sh` is the single source of truth for the "is this autodream's own session?" predicate: lists them, `--delete` purges the backlog, `--filter` excludes them. `run.sh` enumeration pipes through `--filter` so pre-fix transcripts are never triaged.
- **Sleep-resilient retry.** `run.sh` retries L1 over only the still-missing sessions across network/sleep gaps (`AUTODREAM_L1_ROUNDS`, `wait_for_network`), retries L2 until a report lands (`AUTODREAM_L2_ATTEMPTS`), and short-circuits via an idempotency guard when a report already exists (`AUTODREAM_FORCE=1` to rebuild). The launchd example now schedules several morning catch-up triggers and documents a `pmset` scheduled wake.

A new PROMPT.md "Autodream self-audit" section turns the lens on the pipeline: it flags self-pollution regressions, pipeline-capacity issues (oversized transcripts), and retry/sleep health, and proposes concrete cc-autodream source fixes since the user authors the tool.
